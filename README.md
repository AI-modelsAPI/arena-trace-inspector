# Arena Trace Inspector 1.4.0

## 1.4.0：命中才改名 + 一键清理算式对话 + 随机算式探测

- **自动探针改为命中目标才重命名**：某轮抽到的模型命中你的目标时，才把该对话改名为模型名并停下；未命中的轮次**保留算式标题**（如 `7+7=`），作为可清理的探测残留。自动抽卡仍每轮改名。
- 新增 **一键清理探测残留** 按钮：直接归档侧栏中**标题为纯算式**的对话（`N+N=`、`2+3=`、`5*5=` 等），这类标题只可能是探针未命中留下的。已命中改名成模型名的对话、你手动创建/命名的对话、以及当前打开的对话都会保留。逐个走 Arena 官方 Archive 菜单，不弹二次确认；归档不是永久删除，可在 Arena 归档中找回；清理中可再次点击停止，连续失败自动中止。
- 探测/抽卡提示语从固定 `1+1=` 改为内置 **50 条**互不相同的算式（`1+1=` … `50+50=`），每轮**随机发送一条**。
- 关于「同一对话内模型是否会变」：实测在已探测对话里连续追问，模型保持不变（同一会话内有模型黏性）；因此每个"模型名对话"可当作该模型的稳定工作入口。想长期固定用某模型，也可用 Arena 的 Direct 模式直接选定，无需反复探测。

## 1.3.1：修复扩展重载后浮层卡死

- 修复重新加载扩展但未刷新已打开的 Arena 页时，注入脚本上下文失效（`Extension context invalidated`）导致浮层永远停在“读取状态…／正在连接扩展”、按钮全灰的问题。
- 上下文失效后浮层不再无限重试：监听按钮变为「刷新页面」，点击即重新加载页面重新注入；自动抽卡／探针按钮锁定并提示先刷新。
- `chrome.runtime.sendMessage` 的同步抛出与 Promise 拒绝都会被识别为上下文失效，不再吞进重试循环。

## 1.3.0：一键全自动开对话并发送

- 点击 **自动抽卡** / **自动探针** 即开始，不必先点「开启监听」。
- 流程：开启监听 → 点击 New Chat（必要时展开侧栏）→ 切到 Agent Mode → 填入并发送 `1+1=` → SSE 令牌 → Trigger.dev trace → 模型名 → 重命名 → 下一轮空白对话。
- 输入框同时支持 textarea / contenteditable；发送按钮匹配 Send / 箭头提交，不只 `aria-label="Send message"`。

## 1.2.0：探针按真实链路获取模型名

- 自动探针不再空等浮层。发送后走固定链路：页面 SSE 钩子（及调试器）截获 `public-access-token` → GET Trigger.dev run events → 解析 `ai.streamText.doStream` 的 cube 标签。
- 页面 MAIN world 在 `document_start` 挂钩 `fetch`/`EventSource`，调试器失败时仍可取令牌。
- 浮层进度显示当前阶段：截获会话流 / 等待令牌 / 拉取 trace / 已解析模型名。
- 调试器无法附加时改为页面流钩子，不再直接判定监听失败。

## 1.1.0：修复模型识别失败，并增加自动探针

- 修复发送消息后立刻查询 trace 遇到 404／超时／瞬时网络错误就停住的问题：除 401／403／429 外最多重试 8 次。
- 兼容新的 Trigger.dev 公开令牌：支持 JWT `run` 字段；没有 `read:sessions:` 时不再误判为识别失败。
- 兼容 `ai.generateText.doGenerate` 等 span 名称、`data.events` 包装，以及 realtime v2 会话流路径。
- 已识别到模型标签即视为检测成功，不再要求“调用已完成”才重命名／抽卡。
- 新增 **自动探针**：可填写目标型号（默认 `opus5, fable5, gpt6`，可自定义）。命中任一目标即停在该聊天；勾选“找齐全部”则直到列表中的型号都出现过或达到轮数上限。
- 安装与升级步骤见同目录《安装教程.md》。以下为历史版本说明。

## 0.9.1：可配置轮数的自动抽卡

- 先开启当前页监听，再启动“自动抽卡”；按钮左侧可输入 1–100 轮，默认 5 轮。
- 每轮新建聊天、确认 Agent Mode、校验监听后发送一次 `1+1=`，检测完成并重命名后进入新聊天。
- 达到轮数上限或连续检测／重命名失败 3 次停止；草稿冲突、监听中断或手动切换聊天时直接停止，不重复发送。
- 结束或停止时关闭本次流程使用的监听；再次开始前请重新开启。刷新页面不恢复任务。

## 历史：自动抽卡单轮试运行

- 点击浮层“自动抽卡 · 单轮”，新建聊天、确认 Agent Mode、开启监听并只发送一次 `1+1=`；检测完成后重命名，然后进入新的空白聊天并停止。
- 提供“停止抽卡”；不撤回已发出的消息，不归档、不删除聊天。不会覆盖已有草稿，不会自动重发。
- 检测最多等待 180 秒；失败或超时保留聊天并跳过，单轮模式随即结束。当前仅实现 1 轮，不进行无限循环；刷新页面也不会自动恢复。
- 会创建真实聊天并消耗正常使用额度，请按需手动启动。

## 0.4.1：返回会话与刷新后的自动恢复

- 切换会话再返回、刷新 Arena 页面、重新加载扩展后，会按当前会话 ID 读取本机历史，恢复最近保存的型号、Token、trace 费用、调用明细及已有证据。
- 页面浮层在未开启监听时也可显示该会话的已保存结果，明确标注“本地历史 · 非重新验证”，指示灯为黄色。恢复数据不会自动发消息、查询旧令牌或开启调试监听。
- 新的运行令牌到达后切换为“本次捕获”。异步读取带导航校验与失效标记，旧会话的慢读取不能覆盖当前会话或新运行。
- 未保存的会话显示等待／无记录，不借用其他会话的数据；存储读取失败明确提示，不删除历史。
- 保留既有 storage key 和 schemaVersion，无新增权限。历史恢复与监听状态分离：重启后的新捕获仍需手动开启监听。

- 不增加置信度、盲测猜测、代际映射、思考强度或未经测量的时延指标。无新增权限。
- **更新**：在 `edge://extensions` 重新加载原目录的扩展，再刷新 Arena 页并重新开启监听；不要卸载扩展，以免丢失本地历史。

## 新增：Token 与 trace 费用统计

- 浮层和弹窗显示本次运行、会话已捕获累计；历史列表显示各会话累计，弹窗另显示全部已保存记录汇总。JSON 导出包含每个运行的 span 用量和累计值。
- 读取已实测的 `ai.streamText.doStream` 标签：`tabler-hash`（例如 `6.6k`）与 `tabler-currency-dollar`（例如 `$0.0133`）。缩写 Token 标为约数；费用是 trace 展示值的汇总，不是用户账单，也不按公开价格另行估算。没有输入／输出细分时不推算。
- 按 `runId + spanId` 去重。同一运行新快照更新旧 span，新增 span 才累加；不同时累计父级 `ai.streamText`，避免翻倍。每次新收到运行令牌都允许刷新，支持一个运行跨多轮继续更新。
- Token／费用缺失显示“未提供”，不是 0。部分 span 缺失标注“部分缺失”；流尚未结束标注“进行中”。标签未齐时最多尝试 8 次。
- 只统计成功捕获的运行，未监听的对话／旧版未记录用量不会自动补全；累计不是账号总消费。原 0.2.0 会话记录继续保留，重新识别后补充用量。
- 在原目录更新后到 `edge://extensions` 点击扩展“重新加载”，刷新 Arena 页面，再开启监听。本版不增加权限。

## 新增：会话—模型本地存储

- 每次成功识别后，自动保存会话 URL、网页标题（可读时）、会话 ID、运行 ID、模型／提供方标签、首次与最近确认时间。链接由实际流会话 ID 生成，避免串到其他页面。
- 同一会话归为一条记录；同一运行及模型去重，不同运行或模型保留多条观测，不把历史结果当作当前重新验证的结论。
- 插件弹窗下半部分可搜索、查看和点击会话链接，支持导出 JSON。没有开启监听也能看历史；重启浏览器后仍保留。
- 数据存于扩展 `chrome.storage.local`，不云同步、不保存令牌、Cookie、正文或原始 trace。关闭监听只清除临时令牌，不删除记录。卸载扩展会丢失扩展本地数据，需保留时先导出。
- 保存失败时面板明确提示“已识别模型，但本地保存失败”，不会把失败显示成成功。
- **升级**：保留原安装目录，在 `edge://extensions` 对这个扩展点击“重新加载”，接受新增 storage 权限（若浏览器提示），刷新 Arena 页面，再重新开启监听。不要卸载重装。旧版没有保存的历史不会自动补录；需再次识别。

Edge / Chrome Manifest V3 扩展。当前标签页开启后，自动解析 Arena Agent 的 SSE 流记录，提取本次运行公开令牌，用只读 GET 查询 Trigger.dev trace，并显示 `ai.streamText.doStream` 中 `tabler-cube` 对应的模型标签。

1. 打开 `edge://extensions`，开启「开发人员模式」。
2. 点击「加载解压缩的扩展」，选择 **D:\SHUN\arena-trace-inspector**，不是 ZIP，也不是它的父目录。

4. 刷新一个 Arena Agent 页面以加载悬浮面板。
5. 如果 Codex 正在控制这个标签页，先结束该标签页的控制；也不要同时开启这个页面的 DevTools。扩展不会强行夺取已有调试连接。

## 自动执行的范围

- 只附加用户开启的 Arena 标签页，不监听其他标签页；离开 Arena 后自动解除附加。
- 只解析 `/ai-proxy/realtime/v1/sessions/<sessionId>/out` 的成功响应。
- 只接受流记录 `headers` 内的 `public-access-token`，不从对话文本读取令牌。
- JWT 必须包含预期 issuer、`pub:true`、未过期，以及唯一可读取运行（`run` 字段或 `read:runs:` scope）。若令牌带有 `read:sessions:`，必须匹配当前流会话。
- 解码 JWT 不等于验证签名；令牌是否有效由 Trigger.dev 服务端验证。
- 令牌只发往固定 `https://api.trigger.dev/api/v1/runs/<runId>/events`；GET、禁止重定向、不携带 Cookie、不调用写接口。
- 最多读取 8 次 trace，每次间隔 3 秒，请求超时 10 秒。401／403／429 立即停止；404、5xx 与瞬时网络错误会重试。
- 不把 token、Cookie、对话内容或原始 trace 写入 storage、文件、日志或悬浮面板。成功后释放令牌引用；停止后清除内存状态。无遥测、无外部依赖、无远程代码。
- 不提交评价、不自动发消息、不修改模型或运行。

## 显示结果的含义

显示的是服务端 trace 中记录的模型 ID，不是对底层权重身份的独立证明。若 trace 返回多个模型标签，会全部列出；无标签时显示未确认，不通过文风猜测，不生成百分比置信度。

## 排错

- **无法附加调试器**：结束 Codex 对该标签页的控制或关闭该页 DevTools，再开启扩展。
- **一直等待令牌**：必须先开启，再发消息；旧消息不能保证回放。等回复结束后检查。Arena 流格式发生变化也会导致等待。
- **有工具栏状态但没有悬浮面板**：刷新 Arena 页面；安装前的页面没有自动加载 content script。
- **401 / 403**：当前令牌过期或服务端不允许该运行的 trace，扩展不会绕过；发送新消息可重新验证。
- **无模型标签**：服务端可能移除或改变标签；不会用排行榜名称填充。
- **调试提示条**：来自浏览器的 `debugger` API，可用来确认捕获正在进行；不要在测试期间关闭提示条。
